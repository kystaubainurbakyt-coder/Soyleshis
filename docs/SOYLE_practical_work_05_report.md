## 1. Жұмыстың мақсаты

SOYLE қосымшасына REST API арқылы серверден дерек алу, жаңа дерек жіберу, бар деректі өзгерту және жою мүмкіндіктерін қосу. Асинхронды сұрауларды, жүктелу мен сәтті орындалу күйлерін, сервер және желі қателерін өңдеу, сондай-ақ алынған деректі жергілікті Hive қорымен байланыстыру.

## 2. Жоба және REST API таңдау

SOYLE — Flutter арқылы жасалған қазақ тілін үйренуге арналған қосымша. REST тәжірибесі жеке жазбаларға жақын болғандықтан, практикалық прототипте посттар дерегімен жұмыс істейтін JSONPlaceholder тест API таңдалды. HTTP сұрауларын орындау үшін Dart-тың көп платформалы `http` пакеті қолданылды.

**Негізгі ресурс:** `https://jsonplaceholder.typicode.com/posts`  
**Демонстрациялық пайдаланушы:** `userId=1`

JSONPlaceholder — әзірлеу мен прототипке арналған жалған API. Ол POST, PUT және DELETE сұрауларына жауап береді, бірақ сервердегі бастапқы деректерді тұрақты өзгертпейді. Сондықтан операция нәтижесі интерфейсте бірден көрсетіліп, Hive-та аккаунтқа байланған жергілікті кэшке жазылады. Келесі GET жауабы кэшпен біріктіріледі.

## 3. Endpoint тізімі және операциялар

| № | HTTP әдісі | Endpoint | Операция | Нәтиже |
|---:|---|---|---|---|
| 1 | GET | `/posts?userId=1` | Сервердегі посттар тізімін алу | JSON тізімі `RemotePost` модельдеріне түрленеді |
| 2 | POST | `/posts` | Жаңа пост жіберу | Жауаптағы жаңа пост алынып, кэшке қосылады |
| 3 | PUT | `/posts/{id}` | Постты толық жаңарту | Өзгертілген пост интерфейсте және кэште көрсетіледі |
| 4 | DELETE | `/posts/{id}` | Постты өшіру | Пост тізімнен алынып, Hive-та өшірілген күй ретінде белгіленеді |

## 4. Деректер моделі және HTTP іске асырылуы

Серверден келген JSON `RemotePost` класына түрленеді. Модельде `localId`, `ownerId`, `serverId`, `userId`, `title`, `body` және синхрондау күйі бар. `localId` сервер жалған немесе қайталанатын ID қайтарса да, жергілікті жазбаны тұрақты тануға мүмкіндік береді.

`RemotePostApi` класы GET, POST, PUT және DELETE сұрауларын орындайды. Барлық сұраулар `async`/`await` қолданады. Жауап статусы тексеріледі; JSON пішімі жарамсыз болса, `RestApiException` қайтарылады.

| Күй | Қосымшадағы әрекет |
|---|---|
| Loading | Сұрау кезінде экранда `LinearProgressIndicator` көрсетіледі |
| Success | GET/POST/PUT/DELETE сәтті аяқталғанда хабарлама шығады |
| Server error | 5xx жауапқа сервер қатесі көрсетіліп, жергілікті дерек сақталады |
| Offline | Желілік сұрау сәтсіз болса, Hive-тағы кэш көрсетіліп, ескерту беріледі |
| Timeout | 10 секундта жауап келмесе, timeout күйі көрсетіледі |
| Invalid response / exception | Қате JSON мен басқа сұрау қателері өңделіп, интерфейсте хабарланады |

## 5. Серверлік және жергілікті деректер байланысы

Посттар `soyle_v4_remote_posts` Hive қорабында сақталады. Әр жазба SOYLE аккаунтының `ownerId` мәнімен байланысады. Интернет болмаған кезде экран сол аккаунттың бұрын сақталған посттарын көрсете алады. Серверден жаңа GET алынғанда таза деректер жаңартылып, жергілікті жасалған, өңделген немесе өшірілген өзгерістер біріктіріледі.

REST экранына өту жолы: **Профиль → Менің жазбаларым → бұлт белгішесі**.

## 8. Скриншоттар

Әр суретті төмендегі бос орынға орналастырыңыз. Суретте браузердің мекенжай жолағын емес, қосымша интерфейсін көрсету жеткілікті; қажет жерде операция сәтті орындалған хабарлама да көрінсін.

### Скриншот 1. REST API экраны және GET нәтижесі

**Қай жерден түсіру:** қосымшаға кіріп, Профиль → Менің жазбаларым → бұлт белгішесі. GET аяқталып, посттар тізімі көрінген кезде түсіріңіз. Endpoint тақырыбы және бірнеше сервер посты кадрда болсын.

> **[СУРЕТ 1 ОСЫ ЖЕРГЕ: GET орындалып, сервер посттарының тізімі көрсетілген экран]**

### Скриншот 2. POST — жаңа пост қосу

**Қай жерден түсіру:** «Серверге жазба қосу» батырмасын басып, тақырып пен мәтінді толтырып сақтаңыз. Жаңа пост тізімге қосылғаннан кейін, `POST completed successfully` хабарламасымен бірге түсіріңіз.

> **[СУРЕТ 2 ОСЫ ЖЕРГЕ: POST сәтті болып, жаңа пост тізімде көрінген экран]**

### Скриншот 3. PUT — постты өзгерту

**Қай жерден түсіру:** посттағы қарындаш белгішесін басып, тақырыбын немесе мәтінін өзгертіп сақтаңыз. Жаңартылған мән мен `PUT completed successfully` хабарламасын түсіріңіз.

> **[СУРЕТ 3 ОСЫ ЖЕРГЕ: PUT-тен кейін жаңартылған пост]**

### Скриншот 4. DELETE — постты өшіру

**Қай жерден түсіру:** посттың себет белгішесін басып, өшіруді растаңыз. Өшірілген пост тізімде жоқ екенін көрсететін экранды түсіріңіз.

> **[СУРЕТ 4 ОСЫ ЖЕРГЕ: DELETE-тен кейінгі жаңарған тізім]**

### Скриншот 5. Офлайн және кэш күйі

**Қай жерден түсіру:** алдымен GET арқылы посттарды жүктеңіз. Chrome DevTools → Network → Offline режимін қосып, экрандағы жаңарту батырмасын басыңыз. Офлайн ескертуі мен Hive-та кэштелген посттар көрінген кезде түсіріңіз. Содан кейін Offline режимін өшіруді ұмытпаңыз.

> **[СУРЕТ 5 ОСЫ ЖЕРГЕ: интернет өшірулі кездегі кэш пен офлайн хабарламасы]**

### Скриншот 6. Loading және timeout күйі

**Қай жерден түсіру:** DevTools → Network → Slow 3G таңдап жаңартыңыз; жүктелу индикаторы көрінген сәтті түсіріңіз. Timeout қатесін көрсету үшін жауапты 10 секундтан ұзақ ұстайтын баяу профиль қолданыңыз.

> **[СУРЕТ 6 ОСЫ ЖЕРГЕ: loading индикаторы немесе timeout қатесі]**

### Скриншот 7. Тест нәтижесі

**Қай жерден түсіру:** жоғарыдағы `flutter test` командасын іске қосып, терминалда тест нәтижелері аяқталған кезде бүкіл қорытындыны түсіріңіз. Тесттер өтпей қалса, оны жасырып қоймай, алдымен қатесін түзетіңіз.

> **[СУРЕТ 7 ОСЫ ЖЕРГЕ: flutter test қорытындысы]**

## 9. Қорытынды

SOYLE қосымшасына JSONPlaceholder серверімен әрекеттесетін REST прототипі енгізілді. Қолданба серверден посттарды алып көрсетеді, жаңа пост жібереді, барын өзгертеді және өшіреді. Жүктелу, сәтті жауап, сервер/желі қатесі, жарамсыз жауап және timeout жағдайлары қарастырылған. Сервер дерегі пайдаланушы аккаунтына байланысты Hive жергілікті кэшімен біріктіріледі. JSONPlaceholder жазу әрекеттерін серверде тұрақты сақтамайтыны есепте ескертілді.
